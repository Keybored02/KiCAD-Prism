# KiCAD Prism v4.0.0-alpha

This release promotes the accumulated development work since v3.0.2-alpha
straight to v4.0.0-alpha. The planned v3.1 release is superseded; there is no
intermediate 3.x upgrade requirement.

**Upgrade prerequisite:** populated pre-epoch-2 catalogs require a planned
catalog cutover. Back up and verify the whole deployment, export and verify
non-CERN survivors, and complete the preflight and collision checks before the
catalog-only reset. Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/UPGRADES.md#catalog-epoch-2-cutover).
Do not start the new application on an unprepared legacy catalog. Returning to
a pre-epoch-2 release requires its matching backup, not just older images.

## Release Studio

- Adds the Source → Identity → Manufacturing → Build → Outputs → Publish flow
  for manufacturing releases from a committed KiCad revision.
- Selects the board, schematic, design variant, and KiCad BOM preset from that
  revision, including an older revision entered as a full commit SHA.
- Captures the release tag and drawing identity before building, checks remote
  tag availability, and offers manufacturing/assembly settings and vendor packs.
- Produces fabrication, assembly, composed documentation, evidence, and dossier
  outputs, with live build logs and inspectable PDFs and members.
- Binds Designer and QA approvals to the dossier digest; unwaived DRC/ERC
  errors block sign-off unless an administrator records an override.
- Publishes approved dossiers and ready vendor packs to GitHub or GitLab
  Releases, including explicitly configured self-managed GitLab hosts.
- Improves document crop/placement, KiCad stroke text, legacy testpoint
  references, partial-view failure handling, and bounded Git subprocess cleanup.

Signed policy evaluation, cryptographic attestations, and offline verification
remain outside this release. See [Release Studio](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/release-studio/README.md).

## Component catalog and Library Manager

- Introduces component-as-part identity, with immutable revision-owned symbol,
  footprint, 3D, and other typed representations, including a designated
  placement representation and alternate complete pairs.
- Adds the guarded epoch-2 migration tooling for non-CERN survivor archives,
  catalog reset, and restoration with checksum and identity checks.
- Expands component authoring, metadata and inventory editing, revision evidence,
  release review, representation availability, and revision-specific downloads.
- Organizes Import Center around library and project-component sources, with
  proposal remediation and selected/all-project import workflows.
- Adds live symbol/footprint asset previews and pin-to-pad cross-probing.
- Centralizes workflow/role policy and strengthens stale-revision conflict
  responses, stable pagination, resumable validation, and permanent job-failure
  classification.
- Decomposes catalog services while retaining the compatibility facade and
  enforcing architecture and byte-identity checks.

See [Library Manager](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/LIBRARY_MANAGER.md) and [upgrades](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/UPGRADES.md).

## Desktop KiCad Remote Symbol Provider

- Refreshes the catalog finder and component-detail experience, including live
  authenticated previews and representation-aware placement.
- Pages through results, cancels superseded searches, and exposes retryable
  detail/preview and reauthentication states.
- Gives the KiCad bridge session ownership and prevents duplicate placement
  dispatch; failed requests are not reported as successful placement starts.
- Bounds transfer logs and redacts credentials.

See [Remote Symbol Provider](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/REMOTE_SYMBOL_PROVIDER.md).

## Design review and viewer tools

- Adds component/net search and richer selection navigation and cross-probing.
- Adds pad-number and pad/track/via net-name toggles under Objects & filters.
- Supports multiple highlighted nets through Shift-click, lists the highlighted
  set, and emphasizes the same set in compatible 3D views.
- Adds per-net PCB routing statistics and reconciles schematic/board net names
  through shared connectivity.
- Keeps highlights across deep zoom, preserves readable labels during
  highlighting, and avoids rebuilding labels on every zoom operation.
- Improves selection inspector, resizable panels, project-title layout,
  schematic repainting, semantic-viewer reload ownership, and empty-click
  selection behavior.
- Ships the upstream ECAD viewer fixes through comment-anchor resolution
  (ecad-viewer PR #43). Filled-zone interior net labels remain reverted.

See [project review](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PROJECT_WORKFLOWS.md#pcb-labels-and-net-review).

## Design variants

- Discovers the variant catalog for the selected project revision and stores
  the selected variant in shareable URLs.
- Applies effective assembly state to schematic, PCB, BOM, inspector, and search.
- Hides effective DNP components in 3D with a Show DNP override, and supplies the
  same variant catalog to Release Studio.
- Distinguishes unavailable/unknown variants, absent data, and load failures.
  Unknown variant links remain intact while the default assembly is displayed.

Rule-area DNP is diagnosed but not applied; ambiguous alternate footprints stay
visible with a notice. Assembly Assistant output remains reference-assembly
output. See [design variants](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PROJECT_WORKFLOWS.md#design-variants).

## Live comments and issue publishing

- Adds live project and comparison comment updates across API workers, durable
  replay on reconnect, bounded delivery, and HTTP refresh fallback.
- Preserves creation-commit provenance and append-only anchor binding history.
  Missing/ambiguous objects stay available for review and explicit reattachment;
  legacy unpinned threads remain distinguishable.
- Adds administrator-managed code hosts, connected accounts, and per-project
  issue-publishing settings.
- Publishes threads to GitHub/GitHub Enterprise and GitLab.com/self-managed
  GitLab issues; mirrors replies and thread changes and shows sync/retry state.
- Adds encrypted connector credentials, webhook hints and polling, provider
  selection, and recovery from lost remote responses.
- Supports GitLab and Gitea/Forgejo account linking. Gitea/Forgejo issue
  publication is not included.

Local Prism comments remain authoritative and usable during tracker outages.
Mentions do not create a Prism inbox or email notification. See
[live comments](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/architecture/live-comments.md),
[GitHub setup](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/GITHUB_APP_SETUP.md), [GitLab setup](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/GITLAB_SETUP.md), and
[tracker operations](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/TRACKER_INTEGRATION.md).

## Git projects, history, and workspace

- Imports multiple KiCad projects from one directory with distinct project
  anchors and thumbnails; resolves project/title-block text variables.
- Fetches project remotes automatically every five minutes by default, with
  `PRISM_AUTO_SYNC_INTERVAL_SECONDS=0` to disable background fetching.
- Shows remote branch tips consistently and handles commit trees with submodules.
- Plans imports before cloning/registration and exposes permission-checked
  retry of post-import follow-up work.
- Opens supported non-CAD commit files with their proper content types and
  improves project paging, gallery layout, repository links, and refresh errors.
- Prevents stale session/request responses from overwriting current workspace,
  import, or component selections.

## Comparison, authentication, and reliability

- Makes comparison selection and presentation URL-owned, improves focused layer
  isolation and cross-probing, and strengthens independent revision evidence.
- Reduces repeated comparison parsing through bounded content caches and improves
  compressed responses and polling.
- Adds optional email/password authentication alongside OIDC, administrator
  password reset, remember-me sessions, and login rate limiting.
- Moves blocking authentication, comment, catalog-upload, and metadata work off
  asynchronous request paths.
- Recovers lazy-loaded UI sections after redeployment, improves PDF previews,
  and strengthens frontend lifecycle/accessibility checks.
- Hardens backups to use actual Compose payload mounts, reject overlapping
  roots, stage restored files, restore PostgreSQL transactionally, and report
  application stop/start failures.

## Dependencies and experimental geometry

- Pins published `kicad-monkey==2026.9.7` and `kicad-cruncher==2026.9.7`, with
  `wn-geometer==2026.9.7` in the resolved Python graph.
- Locks Python 3.12.13, Node 22.23.2, both npm workspace graphs, the KiCad image,
  and native helper source/toolchain dependencies; CI checks runtime identity.
- Includes the experimental Rust PCB geometry/packed semantic mesh and native
  board-body pipeline. **Normal deployments use
  `PRISM_PCB_GEOMETRY_BACKEND=legacy`.** Rust and Python-copper require explicit
  selection; installing the helper does not activate them.
- Rust rejects helper/identity/unsupported-geometry failures. Performance
  benchmarks do not establish full legacy geometry parity; component-model
  export still depends on KiCad CLI.

See [dependencies](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/DEPENDENCIES.md) and
[experimental geometry](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v4.0.0-alpha/docs/PCB_RUST_GEOMETRY.md).

## Deployment and upgrade checks

The release is an alpha, with Linux AMD64 images and a digest-pinned deployment
archive. It publishes only the `4.0.0-alpha` image tag, not stable floating tags.
The archive includes these notes, the upgrade runbook, backup tooling, and
checksums. Publication requires the main commit Quality gate and the release
stack image smoke test.

Before reopening an upgraded instance, verify login; project schematic/PCB/3D;
variants; comparison; comments and reconnect; catalog search and default/alternate
placement; imports; Release Studio build and sign-off; and any configured tracker.
Retain the verified pre-upgrade backup and survivor archive.
